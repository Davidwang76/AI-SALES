# 三方协作的季月旬目标制定

本轮替换手工目标树。旧目标数据仍在 goals 表，界面“旧版目标（只读）”可查询；旧写入接口返回409，不能借旧接口绕过确认。新流程使用独立的讨论、材料、版本、确认和复盘记录。

## 实际使用

1. 公司管理员先在“团队与权限”建立至少三个有效账号。发起季度议题时，指定三位不同的上级、下级和秘书。上级须为公司管理员或管理者；下级、秘书可使用执行岗位账号。这些是议题中的参与身份，不是新增的平台级权限。
2. 在“讨论与资料”工作区，上级、下级分别留言，表达方向、依据、资源、可行性和分歧。秘书可以留言，并将会议纪要或从Excel复制的表格粘贴到黏贴板，也可上传CSV、文本或原件。附件可下载。只有本议题秘书可以提交和选择本次起草材料；不需要的材料可暂不纳入起草，原始记录仍保留。
3. 切换至“草案与确认”，点击“请AI拟定目标草案”。后台任务读取所选可读材料、三方意见、已确认上级目标，以及上一旬复盘（如有），调用配置的模型服务。输入会发送至该模型服务。结果中的引文须匹配输入原文，并引用上级、下级和秘书资料；不合格响应不会进入确认流程。
4. 核对草案、引用、待核实项与风险。当前默认按“上级→下级→秘书”依次确认，同一人不能代签其他身份。任何参与人可修订草案，保存为新版本后从上级重新确认；也可说明原因退回讨论。增加观点或材料会使尚未确认的草案失效。历史版本和原确认不被覆盖。
5. 季度目标三方确认后，可建立月度议题；月度目标确认后，可建立当月的旬议题。参与人和上级确认版本自动带入，不重复填写。子周期可继承已确认上级版本中的意见和资料，补充本周期信息后由AI起草，仍需三方确认。上级目标更新后，未对齐的下级草案不能确认。
6. 在“旬复盘与调整”工作区，已确认的旬目标距旬末3天内显示复盘提示，过期仍可复盘。参与人记录实际结果、差距及下一旬调整建议，再引用复盘建立下一旬讨论。如果下一旬目标已经提前制定，则保留旧确认版本、发起调整，重新起草和确认，而不是建立重复目标。跨月须先确认下一月的月度目标；跨季度同理先确认新季度和月份。重复点击建立下一旬会返回同一议题。

## 访问与记录

公司管理员可查看本公司议题；其他账号仅能查看被指定参与的议题。即使是公司管理员，未被指定为三方之一也不能代签、发言或提交秘书材料。每次消息、资料范围变化、草案生成、修订、确认和复盘均有审计。消息、原材料、草案版本、确认、复盘记录在数据库中禁止修改或删除。

AI起草期间输入变化时，过期结果不采用。上级确认版本或上一旬复盘更新时，旧待确认草案被拦截。模型错误和服务中断保留已提交材料，允许重试，不标记为已确认。后台心跳独立更新，避免模型调用期间被误判为工作进程停止。

## 连接AI

本程序不会自带他人的API密钥。先完成服务器更新，再通过服务器终端编辑安装目录下的 `.env`，填入自己的OpenAI兼容模型配置；不要把密钥发到聊天或提交GitHub：

```dotenv
MODEL_API_KEY=填写你自己的真实密钥
MODEL_NAME=填写模型名称
MODEL_ENDPOINT=https://你的模型服务地址/v1/chat/completions
```

若使用OpenAI兼容地址，须支持JSON响应格式。默认地址为 `https://api.openai.com/v1/chat/completions`。保存后在安装目录执行：

```bash
docker compose up -d --no-deps --force-recreate web worker
```

界面的“模型已配置”只代表配置存在，调用成功以后台任务结果为准。未配置时仍可提交留言和资料，但不会伪造AI草案。PDF、照片、截图目前只保存原件，尚未接通OCR，需另补充可读文字；Excel文件请复制表格内容或转CSV。起草内容过大时，由秘书排除不需要的原件并补充可读摘要。

## 验证范围

通过61项后端与领域检查、7条浏览器流程验证。使用独立PostgreSQL数据库检查身份、公司与资料隔离、按序确认、版本不可变、更改输入使旧确认失效、过期模型结果拒绝、错误与重试、上级变更、跨月复盘、重复创建保护，以及下一旬已提前制定时的调整流程。模型适配器的协议和引用校验使用本地测试替身验证；浏览器使用三个独立登录会话贯通季度、月度、旬目标和复盘。没有使用用户真实模型凭据，也没有将测试替身作为生产AI。

本轮不包含OCR、自动读取XLSX、外部提醒或自动代签，不会把模型建议直接作为生效目标。服务器是否已经更新、真实模型是否可达，须以服务器部署和实际调用结果为准。
