## 操作方法

1. 若旧下载仍在重试，先在原终端按 Ctrl+C 停止。
2. 从本次交付消息下载 `portal-v11-offline.tar.gz` 到自己的电脑，通过云终端提供的文件上传功能或 WinSCP/Xftp 上传到服务器 `/home/ubuntu/`。直接上传压缩包，电脑端不用解压。
3. 按交付消息提供的 SHA256 对整个压缩包做校验；在新建临时目录中解压，避免覆盖未知的旧文件。再在包目录运行 `sha256sum -c SHA256SUMS` 核查所有文件。
4. 使用 sudo 执行解压目录内的 `update.sh --offline /home/ubuntu/ai-sales-9f45fcd`。`--offline` 必须保留；正式运行不设置演练用 `PORTAL_VERIFY_URL`。

脚本先核对原基线、原服务和 HTTPS 健康，备份原源码与文件权限并保留旧镜像。候选 web 只映射本机随机端口，检查通过后仅切换 web；worker、数据库和网关容器 ID 必须保持不变。前端源文件也会按原权限更新，便于以后接续维护。

这次构建不需要外部下载；仍会对现有数据库、内部候选地址及 `https://49.233.175.166` 发起正常的健康、公共入口、静态资源与权限 GET 检查，TLS 校验保持开启。若现有 HTTPS 已故障，脚本会在切换前停止，需要先排查该故障。
